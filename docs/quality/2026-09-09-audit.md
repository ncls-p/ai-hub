## Fixed behavior

- Public conversations distinguish unavailable/revoked links (404/410) from temporary server, network and JSON failures. Temporary failures expose a localized retry action.
- Switching the public share identifier unmounts the old content immediately and cancels its request. Late responses cannot populate the next share.
- Every response gets `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`; the framework identification header is disabled. Existing preview framing and route-specific content policies remain compatible.
- The organization logo picker and its file input have localized accessible names. The input is disabled for read-only users.
- The example Redis URL matches the development Compose port, 16379.

## Test quality

The image-card and public-conversation tests now mount the actual React components, translations, preview dialog and Markdown renderer in jsdom instead of looking for strings in implementation files. They exercise image preview open/close, actual Markdown rendering, 404/410, server/network failure, retry and switching shares.

Vitest requires every executed test to reach an assertion. The metadata validation test explicitly asserts that a valid name does not throw. E2E assertions for sign-in/sign-up validation, sign-out, assistant/provider controls, searches, filters, setup and the composer no longer silently succeed when those controls are absent. Marketplace tests exercise deterministic loaded, empty, filtered, detail and failed states. Their catalog responses are simulated intentionally; publishing/import authorization is exercised separately against real APIs and PostgreSQL.

The normal login fixture restores the primary project. The explicit credential-login helper preserves selection for the dedicated persistence scenario, which also restores its changed preference. This fixes repeated-run failures caused by a previous run leaving the admin in the transfer destination project.

Remaining source-policy tests (packaging, deployment configuration, layout conventions and accessibility naming conventions) are supplementary structural guardrails, not evidence that an interface works. Browser assertions provide the behavioral evidence. Neither passing tests nor the configured coverage percentage implies exhaustive coverage of the application.
